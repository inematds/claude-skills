MODULE 6.1

🎷 Improvised Intelligence

The improv skill: a single command that researches a business, builds the pitch, creates the brand system, architects a team of agents—and, underneath it all, observes what you create and offers to turn it into new skills. Let’s unpack the three benefits and see how to trigger each phase.

🎷 What is a mega-skill

Most skills solve a task: generate an itinerary, review a workflow, audit a website. A mega-skill does something else—it weaves together multiple phases of complex work under a single entry point. You say one sentence, and the skill guides research, proposal, brand, and operations like a pipeline.

🎯 The definition

Improvised Intelligence defines itself as a unified engine that takes a business from "cold prospect" to "fully operationalized client"—with workflow capture at every step. It orchestrates four interconnected phases and a fifth that observes everything:

  • •PROSPECT — competitive intelligence and market research on the target.
  • •PITCH — a personalized proposal with 5 deliverables that close the deal.
  • •BRAND — guided creation of a brand book in 8 phases.
  • •OPERATE — a team of AI agents that runs ongoing operations.
  • •CAPTURE — detects repeatable patterns and generates new skills from completed work.

💡 Practical tip

The mega-skill doesn’t start out big on purpose. It grows when you realize that several of your skills always run in the same order. Instead of calling three skills in sequence every time, you combine them under one command and a phase detection table. Size isn’t the goal—eliminating manual coordination is.

The first benefit is the most visible: the skill replaces an entire agency workflow — research, pitch, brand strategy, and AI operations — in a single chain of commands. What would normally pass through several people and several tools happens through simple phrases.

📈 Benefit 2: gets smarter with every session

The second benefit is the most interesting for anyone studying skill architecture: Improvised Intelligence gets smarter with every session. A built-in detector — the Workflow Spotter — captures what you do and turns it into reusable skills.

🔎 When the Spotter triggers

It evaluates "is this worth turning into a skill?" whenever ANY of these happens:

  • • 10+ back and forth in a single project
  • • 5+ tool calls for the same result
  • • 3+ output files created
  • • A complete Research → Analysis → Creation → Delivery arc
  • • The user says “let’s do this again” or “for next time”

The detection checklist

Before suggesting a skill, the skill asks itself—if 3+ are checked, it offers:

□ Was it more than a simple Q&A?

□ Did it involve 3+ distinct phases?

□ Were reusable artifacts created?

□ Would the user probably do something similar again?

□ Could 50%+ of the work be systematized?

□ Did I discover something the "future Claude" shouldn't have to rediscover?

💡 Practical tip

This is the same self-improvement principle you'll see in Taproot (6.2) and on the /sessionend (6.3): capture the work instead of letting it evaporate. Steal this idea for any skill of yours — a block at the end that asks "does this keep happening? want me to save it?".

⚙️ Benefit 3: born in production

The third benefit is a quality guarantee: every piece of the skill runs on real business fronts now — was built in production, not in theory. That changes everything about the quality of the defaults, brand rules, and description.

⚠️ Attention: production skills have production rules

Skills born in production carry explicit rules that you wouldn’t come up with on paper: a sensitive information protocol (never automatically learn financial, legal, or health data), channel limits, a locked brand voice. When writing your own, follow this discipline—clear constraints are more valuable than vague freedom.

Quality standard before delivering any output

  1. Specificity — refers to the real business, not placeholders?

🗺️ Phase Detection: The Command Chooses the Path

How can such a large skill have a single entry point without turning into a maze? With a phase detection table. The skill reads the request, matches it to the right phase, and routes itself. If it’s ambiguous, it asks one disambiguation question — not an interrogation.

1

Read the request

"pitch X" → PROSPECT+PITCH · "brand book for Y" → BRAND · "build agent system" → OPERATE · "onboard Z" → all in sequence.

2

Disambiguates with a question

If you can’t decide: "Are we prospecting, onboarding, or building operations?" Just one. No 10-item menu.

3

Runs the phase (or chain)

Each phase can run on its own or in a sequence. At the end, the CAPTURE phase evaluates whether what happened is worth turning into a skill.

💡 Reusable pattern

The “phase detection table” is one of the most useful tricks for any skill with modes. Instead of a confusing mental if-else, you give Claude a table Se o usuário diz → Fase → Ação. It matches the request and takes action. Copy this table into your next multi-mode skill.

🔁 How to Use It in Practice

In practice, you trigger the skill with command phrases. Each one starts the right phase; together, they run the entire chain. Below are copyable prompts to try—adapted for general use, without tying them to any specific brand.

Prompt · trigger a phase 
pitch [nome do negócio]

Pesquise o negócio (avaliação, concorrentes, o que os clientes
procuram), encontre a "lane não reivindicada" dele e monte:
uma landing personalizada, 3 PDFs (calendário de conteúdo,
posicionamento, snapshot de mercado) e um roteiro de vídeo curto.
Prompt · guided brand 
build brand book for [cliente]

Conduza as 8 fases guiadas. NÃO pule fases nem assuma respostas:
descoberta → missão → promessa → taglines → voz e tom →
regras de vocabulário → bancos de frase por avatar → compilar.
Confirme comigo a cada fase antes de seguir para a próxima.
Prompt · capture the workflow 
capture this workflow

Run the detection checklist on what we just did.
If 3+ items match, propose a new skill: suggested name,
what it would include, and the trigger phrases. Don’t build it yet —
just show me the proposal.

💡 Personalize before using it for real

For real-world use, replace the brand voice and defaults with the your identity (PDF colors, signature phrase, tone). The mega-skill was designed to coexist with your philosophy—not impose the original author's.

🏋️ Hands-on exercises

1

Map your phases

Choose a task of yours that always follows the same order. List the phases (3 to 5) and write the detection table: "If I say X → phase Y → action Z".

2

Write the capture checklist

Adapt the Workflow Spotter's 6-question checklist to your domain. Set the threshold (how many items need to match to suggest a skill).

3

Create a runnable SKILL.md (mini mega-skill)

Write a SKILL.md in two phases under a single command, with a detection table and a capture block at the end. Skeleton:

--- name: meu-pipeline description: "Two-phase pipeline in one command. Use when the user says 'run [X]' or 'pipeline for [X]'. Detects the phase from the request. Also triggers on 'capture workflow.'" --- # My Pipeline ## Phase detection | User says | Phase | Action | |--------------------|-----------|--------------------------------| | "run [X]" | PHASE 1→2 | Research, then deliver | | "just research [X]"| PHASE 1 | Dossier only | | "capture workflow" | CAPTURE | Evaluate and propose a new skill | ## Phase 1 — Research (steps) ## Phase 2 — Delivery (steps) ## Capture At the end, run the checklist. If 3+ items match, propose a skill.

Save in ~/.claude/skills/meu-pipeline/SKILL.md, open Claude Code and test with "run acme".

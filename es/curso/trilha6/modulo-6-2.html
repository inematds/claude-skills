MÓDULO 6.2

🧬 Taproot: árbol de skills (meta-skill)

No una skill que ejecuta una tarea, sino una que enseña al agente a mejorar con el tiempo. Un CLAUDE.md que le da a tu agente un nombre, clase, nivel, XP y un árbol de skills que puedes abrir en el navegador. Veamos los tres beneficios, el flujo de uso y la visión a futuro.

1

🧬 Qué es una meta-skill

Hasta ahora construiste skills que hacen cosas. Una meta-skill es diferente: no ejecuta una tarea de dominio — gobierna cómo nacen las otras skills, adquieren peso y se conectan. Taproot es exactamente eso: un CLAUDE.md que enseña al agente a mejorar con el tiempo.

🎮 El agente se convierte en un personaje

Taproot le da atributos de RPG a tu agente, y esto no es un adorno, es una mecánica de incentivos:

  • •Nombre y clase — una identidad que persiste entre sesiones.
  • •Nivel y XP — progreso medible que crece cuando se crean y usan skills.
  • •Árbol de skills — un ecosistema interconectado que abres en el navegador.

💡 Por qué CLAUDE.md, no SKILL.md

Una skill común (SKILL.md) se descubre y se activa según el contexto. Una meta-skill se encuentra en el CLAUDE.md — el archivo que está siempre en el contexto del agente en ese proyecto. Es el lugar adecuado para las reglas que deben regir todo el comportamiento, y no solo una tarea. Por eso "gobierna" en vez de "ejecutar".

Gobierna

No ejecuta tareas.

CLAUDE.md

Siempre en contexto.

RPG

Nivel, XP, clase.

Árbol

Visible en el navegador.

2

⚡ Beneficio 1: skills autogeneradas

El primer beneficio es el corazón del concepto: skills que se generan solas. Cuando el agente comete el mismo error dos veces, crea una corrección permanente. Cuando detecta un patrón recurrente, lo formaliza en una skill reutilizable. Las skills ganan XP, tienen niveles de rareza (de Común a Legendaria) y se ramifican en un ecosistema conectado.

1

Error detectado dos veces → corrección permanente

La primera vez es un accidente. La segunda, el agente entiende que es un patrón y crea una regla fija para no volver a cometerlo.

2

Patrón recurrente → skill formalizada

Algo que haces repetidamente se convierte en una skill con nombre, descripción y activadores: parte de tu arsenal.

3

XP crea pesos que incentivan el ciclo

Las puntuaciones de XP generan ponderaciones que incentivan el ciclo de creación de skills: el sistema está diseñado para alimentarse a sí mismo.

RarezaLo que suele significar
ComúnCorrección pequeña, aplicada pronto y con frecuencia.
Inusual / RaraPatrón de dominio que demostró ser útil en varios casos.
LegendariaSkill central, muy utilizada y conectada con varias otras.

💡 La regla de oro: "dos veces"

El umbral de «cometer el mismo error dos veces» es deliberado. Una vez puede ser ruido; dos veces es una señal. Usa ese mismo disparador en tu meta-skill: evita crear una skill para todo (ruido) y garantiza que lo que se convierte en skill realmente se repita.

3

📐 Beneficio 2: planifica antes de construir

El segundo beneficio combate la costumbre más común de los agentes: ponerse a programar a partir de premisas equivocadas. Taproot analiza las brechas en sus propias suposiciones y propone un plan de desarrollo antes de escribir una línea de código. Pregunta lo que no sabe en vez de adivinar.

✓ Agente que planifica

  • ✓Analiza las brechas de sus propias suposiciones.
  • ✓Propón un plan de build antes de programar.
  • ✓Pregunta explícitamente lo que no sabe.
  • ✓Corriges el rumbo en el plan, a bajo costo.

✗ Agente que adivina

  • ✗Asume los requisitos y empieza a escribir código.
  • ✗Descubre las brechas solo cuando falla el build.
  • ✗Corriges el rumbo en el código terminado, a un costo alto.
  • ✗La repetición del trabajo se vuelve la norma.

🔎 Análisis de brechas en la práctica

El agente enumera lo que necesita saber, marca lo que ya sabe, identifica lo que falta y convierte las brechas en preguntas concretas. Solo entonces propone el plan. Es el mismo principio de «medir dos veces, cortar una» — aplicado al software.

Suposiciones

Enumeradas, no ocultas.

Brechas

Se convierten en preguntas.

Plan

Antes del código.

Corrección

Barata, dentro del plan.

🌳 Beneficio 3: un árbol que puedes ver

El tercer beneficio es lo que capta la atención: un árbol de skills que realmente puedes ver. Abre el HTML generado y sigue el crecimiento del agente: tarjeta de perfil, arsenal de skills y un grafo de red que muestra cómo se conectan las skills. Niveles, XP, progresión de clase: todo visual.

💡 Por qué importa hacer visible el progreso

Cuando tú ve qué sabe el agente —y qué le falta— te ayuda a tomar mejores decisiones: dónde invertir, qué skill aún es débil y cuáles se conectan. La visibilidad cambia el comportamiento. Por la misma razón tenemos dashboards en lugar de logs sin procesar.

5

📥 Cómo usar: del CLAUDE.md al árbol

El flujo de adopción es sorprendentemente corto para algo tan poderoso. Toma el CLAUDE.md del repositorio, colócala en la raíz del proyecto, abre Claude Code, haz una incorporación de ~30 segundos, construye algo y abre el árbol.

1

Deja el CLAUDE.md en la raíz

El archivo va a la raíz de tu proyecto. A partir de ahí, siempre forma parte del contexto del agente en ese repositorio.

2

Abre Claude Code y realiza el onboarding

~30 segundos: el agente recibe un nombre, una clase y un estado inicial. No tienes que configurar nada manualmente.

3

Construye algo → abre el skill tree

Trabaja con normalidad. El agente captura patrones y gana XP. Abre la página de visualización y mira cómo crece el árbol.

Prompt · iniciar la meta-skill 
# Coloque o CLAUDE.md na raiz e abra o Claude Code.
# Depois, dispare o onboarding:

"Inicie o onboarding do Taproot: me dê nome e classe ao agente,
crie o estado inicial e me explique como ganho XP."

# Trabalhe normalmente. Quando quiser ver a evolução:
"Abra/atualize a árvore de skills (skill tree)."

🧩 Extras incluidos

El repositorio también incluye la página de vista previa del Skill Tree y un complemento opcional de orquestación multiagente — lo que conecta de forma natural con el tema del próximo módulo (memoria entre agentes).

6

🔮 La visión de futuro

Vale la pena ver hasta dónde puede llegar la idea, no porque todo esto ya exista, sino porque pensar en la visión te ayuda a diseñar tu propia meta-skill con espacio para crecer. La propuesta apunta en cuatro direcciones.

🛒 Marketplace de skills

Compartir y vender skills individuales que generó el agente. Importar/exportar con un solo archivo: "esta es la skill que creó mi agente después de encontrarse con el mismo error 3 veces".

👤 Perfiles de la comunidad

Cada persona obtiene un escaparate que muestra el personaje del agente, su arsenal y sus estadísticas. Explora los agentes de los demás y construye sobre lo que aprende la comunidad.

⚔️ Comparación de agentes

Superponer árboles de skills lado a lado. Comparar el crecimiento de tu agente con el de otros, en fichas de estadísticas al estilo RPG.

🧬 Fusión de skills

Cuando dos skills se activan juntas con frecuencia, se fusionan en una skill compuesta. El agente no solo colecciona skills: las sintetiza.

💡 Qué llevar a tu meta-skill

Aunque no haya marketplace, hoy se pueden aplicar tres ideas: (1) darle una identidad persistente al agente, (2) fomentar la creación de skills con algún tipo de puntuación, y (3) hacer visible el progreso. Empieza poco a poco; la visión amplia marca el rumbo.

🏋️ Ejercicios prácticos

1

Define la regla de "dos veces"

Escribe, en una frase, la regla que activará la creación de una skill en tu agente. Define también qué cuenta como «el mismo error» en tu dominio.

2

Diseña el esquema de XP

Define cuántos XP da cada acción (crear una skill, usar una skill existente, corregir un error) y los umbrales de nivel. Enumera 3 rarezas y el criterio de cada una.

3

Crea un CLAUDE.md de meta-skill ejecutable

Escribe un CLAUDE.md mínimo que le dé identidad al agente y la regla para crear una skill. Esqueleto:

# Agente: {nome} · Clase: {classe} · Nivel: 1 · XP: 0 ## Regla de evolución - ¿Encontraste el mismo error 2x? Crea una corrección permanente en `.agent/skills/{nome-da-skill}.md` y registra +50 XP. - ¿Patrón recurrente (3x)? Formalízalo como skill (+100 XP). - Antes de construir: ejecuta un análisis de brechas y propone un plan. Pregunta lo que no sabes; no hagas suposiciones. ## Estado (actualiza en cada sesión) - Skills: (lista con nivel y rareza) - XP total: (número) · Siguiente nivel en: (número) ## Visualización - Cuando te pidan "árbol de skills", genera/actualiza `skill-tree.html` con perfil + arsenal + grafo de conexiones.

Guarda como CLAUDE.md en la raíz de un proyecto de prueba, abre Claude Code y construye cualquier cosa. Después pide "abre el árbol de skills".

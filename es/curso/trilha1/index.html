🧬 Fundamentos de Agent Skills

Antes de crear cualquier skill, necesitas entender lo que realmente es: un archivo de texto que Claude lee, decide cargar y ejecuta por sí solo. Este recorrido analiza la anatomía de SKILL.md, la mecánica de divulgación progresiva y el arte de escribir descriptions que se activan en el momento adecuado.

1.1 ~40 min

🧬 Anatomía de una Skill

Qué es un SKILL.md, el frontmatter name/description, el cuerpo de instrucciones y cómo Claude descubre y activa la skill por sí solo.

Qué es:

Un archivo Markdown con frontmatter YAML que enseña a Claude a ejecutar una tarea específica cuando se le solicita.

Por qué aprender:

Es la unidad mínima de todo. Quien entiende el archivo entiende el sistema entero.

Conceptos clave:

Texto, no código. Se puede versionar, leer y trasladar entre máquinas.

Qué es:

El identificador único de la skill, en kebab-case, que Claude usa internamente.

Por qué aprender:

Un nombre ambiguo equivale a una skill que nadie encuentra. Es el primer campo que importa.

Conceptos clave:

Breve, descriptivo y estable. Cambiar el name rompe referencias.

Qué es:

La frase que le dice a Claude qué hace la skill Y cuándo usarla. Es lo que lee para decidir si debe activarla.

Por qué aprender:

El 90% del éxito de una skill está aquí. Una descripción débil = una skill muerta.

Conceptos clave:

Hace + Cuándo. Verbos de acción, disparadores concretos.

Qué es:

Todo lo que está debajo del frontmatter: el paso a paso, las reglas, los ejemplos y el formato de salida esperado.

Por qué aprender:

Es donde se define la calidad de la ejecución. Las instrucciones vagas generan resultados vagos.

Conceptos clave:

Workflow, reglas estrictas, formato de salida, principios.

Qué es:

Al principio, Claude solo ve name + description de cada skill: nunca el contenido completo de todas.

Por qué aprender:

Entender esto explica por qué la description lo es todo y por qué demasiadas skills confunden.

Conceptos clave:

Índice ligero, matching semántico, carga bajo demanda.

Qué es:

Cuando la solicitud coincide con una description, Claude carga ese SKILL.md y empieza a seguir sus instrucciones.

Por qué aprender:

Es la diferencia entre una skill que se activa sola y una que tienes que invocar manualmente.

Conceptos clave:

Activación automática, invocación explícita, contexto de la conversación.

1.2 ~40 min

📂 Divulgación progresiva y estructura

Las carpetas references/, scripts/ e assets/, la carga bajo demanda y la regla de oro: mantener el SKILL.md conciso.

Qué es:

Estrategia de mostrar primero solo lo esencial y revelar los detalles únicamente cuando sea necesario.

Por qué aprender:

Es el principio que mantiene el contexto ligero y la skill rápida y económica de cargar.

Conceptos clave:

Capas, bajo demanda, ahorro de contexto.

Qué es:

Archivos de apoyo (templates, design systems, tablas) que el SKILL.md indica leer cuando sea necesario.

Por qué aprender:

Es donde está el detalle que haría que el SKILL.md fuera enorme si estuviera inline.

Conceptos clave:

Documentos de apoyo, lectura condicional, modularidad.

Qué es:

Scripts (Python, shell, etc.) que la skill ejecuta en vez de pedirle a Claude que reescriba la lógica cada vez.

Por qué aprender:

El código determinista es más confiable y barato que regenerar la lógica en cada llamada.

Conceptos clave:

Determinismo, reutilización, separar la lógica de la prosa.

Qué es:

Archivos estáticos — fuentes, imágenes, templates HTML, ejemplos — que la salida usa o referencia.

Por qué aprender:

Mantén la skill autocontenida: todo lo que necesita viaja con ella.

Conceptos clave:

Autocontenido, recursos versionados, ejemplos de salida.

Qué es:

El SKILL.md debe contener el flujo y las decisiones; los detalles más complejos van en los archivos de apoyo.

Por qué aprender:

Un SKILL.md inflado consume contexto cada vez que se activa, incluso cuando no se usa el detalle.

Conceptos clave:

Enrutador, no enciclopedia. Señala, no vuelca información.

Qué es:

El patrón de indicarle a Claude que abra un archivo de apoyo solo en condiciones específicas.

Por qué aprender:

Es lo que transforma un conjunto de archivos en una skill que se navega por sí sola.

Conceptos clave:

Condiciones de lectura, tabla de enrutamiento, activación por tarea.

1.3 ~40 min

🎯 Descriptions que se activan

La anatomía de una description que se activa en el momento adecuado: activadores, ejemplos, antipatrones y —tan importante como— cuándo NO activar.

Qué es:

Toda buena description tiene dos partes: lo que produce la skill y en qué situaciones debe usarse.

Por qué aprender:

Las descripciones que solo dicen "qué hacen" no le dan a Claude la señal de cuándo activarlas.

Conceptos clave:

Capacidad + condición, acción + contexto.

Qué es:

Palabras y pedidos reales ("crea un itinerario", "/travel") que indican que la skill aplica.

Por qué aprender:

Los disparadores concretos aumentan drásticamente la tasa de activación correcta.

Conceptos clave:

Lenguaje del usuario, sinónimos, comandos de barra.

Qué es:

Incluir casos de uso breves dentro de la propia description para orientar el matching.

Por qué aprender:

Los ejemplos le dan a Claude referencias semánticas que las descripciones abstractas no ofrecen.

Conceptos clave:

Casos de uso, anclas, «úsalo cuando...».

Qué es:

Descripciones vagas, demasiado genéricas o puramente técnicas que no dicen cuándo usar la skill.

Por qué aprender:

Reconocer el antipatrón es la forma más rápida de corregir una skill que no se activa.

Conceptos clave:

Vago, redundante, sin disparador, jerga sin contexto.

Qué es:

Deja claros en la description (y en el cuerpo) los casos en que NO debe usarse la skill.

Por qué aprender:

Los falsos positivos dificultan tanto como los falsos negativos. Los límites evitan ambos.

Conceptos clave:

Alcance negativo, "no lo uses para...", desambiguación.

Qué es:

Ejecutar solicitudes reales y variadas para ver si la skill se activa cuando debe y permanece inactiva cuando no debe.

Por qué aprender:

La description es una hipótesis; solo la prueba confirma. Es un ciclo, no un único intento.

Conceptos clave:

Casos de prueba, falsos positivos/negativos, iteración.
